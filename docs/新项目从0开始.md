# 新项目自动化测试：从 0 开始操作指南

这份指南默认你没有自动化测试经验，使用 Windows PowerShell。完成后你可以：

- 检查本机环境是否完整。
- 运行框架自身的离线测试。
- 为新项目编写 API、Web 和 App 自动化用例。
- 生成 Allure 报告并接入 CI。
- 避免密码泄露、生产误操作和测试脏数据。

## 1. 先准备软件

### 1.1 安装 Python

安装 Python 3.10、3.11 或 3.12。安装时勾选 `Add Python to PATH`。

打开 PowerShell 验证：

```powershell
python --version
python -m pip --version
```

如果 `python` 找不到，重新安装并勾选 PATH，或者使用 Windows 的 `py` 命令代替。

### 1.2 安装 Git

```powershell
git --version
```

### 1.3 安装编辑器

推荐 VS Code，并安装 Python 扩展。也可以使用 PyCharm。

## 2. 获取项目并创建虚拟环境

进入你准备存放代码的目录：

```powershell
git clone <你的仓库地址>
cd web-api-app-autotest
python -m venv .venv
```

激活虚拟环境：

```powershell
.\.venv\Scripts\Activate.ps1
```

如果 PowerShell 提示禁止执行脚本，只对当前用户放开签名脚本：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.\.venv\Scripts\Activate.ps1
```

激活后命令行前面会出现 `(.venv)`。以后每次重新打开 PowerShell，都要重新激活。

升级安装工具：

```powershell
python -m pip install --upgrade pip
```

## 3. 按测试类型安装依赖

只做 API 测试：

```powershell
python -m pip install -r requirements-api.txt
```

做 API + Web 测试：

```powershell
python -m pip install -r requirements-web.txt
python -m playwright install chromium
```

做 App 测试：

```powershell
python -m pip install -r requirements-app.txt
```

需要查 MySQL 或 Redis：

```powershell
python -m pip install -r requirements-infra.txt
```

第一次使用、不想区分依赖，可以全部安装：

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
```

框架开发人员还应安装：

```powershell
python -m pip install -r requirements-dev.txt
```

## 4. 第一次运行必须做的两件事

### 4.1 环境体检

```powershell
python scripts/automation.py doctor
```

输出含义：

- `[通过]`：已经满足。
- `[提醒]`：当前测试类型可能不需要，或尚未填写业务配置。
- `[失败]`：必须按后面的提示处理。

### 4.2 框架离线自测

```powershell
python scripts/automation.py self-test
```

这个命令只测试框架代码，不会访问公司接口、数据库、Redis、百度或 Appium。修改 `core/`、`config/`、`fixtures/`、`utils/`、`scripts/` 后，都要先运行它。

## 5. 认识目录

```text
api/                 API 业务封装
pages/               Web Page Object
screens/             App Screen Object
testcases/api/       真实 API 用例
testcases/web/       真实 Web 用例
testcases/app/       真实 App 用例
tests/framework/     框架自身离线测试，不放业务用例
examples/            教学示例，默认不执行
data/                YAML、JSON、Excel、文本测试数据
fixtures/            共享前置条件和自动清理
clients/             MySQL、Redis、通知、邮件客户端
config/              多环境配置
docs/                使用文档
reports/             运行后生成的报告数据，不提交 Git
```

记住最重要的规则：

- 接口地址和请求细节放 `api/`。
- 页面定位器和操作放 `pages/` 或 `screens/`。
- `testcases/` 只描述测试场景和断言。
- 账号、密码、token 不写进代码和 YAML。

## 6. 配置新项目环境

### 6.1 修改非敏感配置

编辑 `config/config.yaml`：

```yaml
sit:
  api_base_url: "https://sit-api.你的公司.com"
  web_base_url: "https://sit.你的公司.com"
  db:
    host: "sit-mysql.你的公司.com"
    port: 3306
    name: "业务库名"

uat:
  api_base_url: "https://uat-api.你的公司.com"
  web_base_url: "https://uat.你的公司.com"
```

先只配置你实际使用的环境。URL 必须以 `http://` 或 `https://` 开头。

### 6.2 创建敏感配置

```powershell
Copy-Item .env.example .env
```

编辑 `.env`：

```dotenv
ENV=uat
TEST_USERNAME=你的测试账号
TEST_PASSWORD=你的测试密码
API_TOKEN=
DB_USER=
DB_PASSWORD=
REDIS_PASSWORD=
```

`.env` 已被 `.gitignore` 排除。不要执行 `git add -f .env`，不要把真实密码发到群聊、截图或文档中。

重新检查：

```powershell
python scripts/automation.py doctor --env uat
```

## 7. 编写第一个 API 测试

假设接口文档里有：

```text
GET /api/products/{product_id}
成功状态码：200
响应：{"code": 0, "data": {"id": 1001, "name": "测试商品"}}
```

### 7.1 新建 API 封装

创建 `api/product_api.py`：

```python
import allure

from api.base_api import BaseApi


class ProductApi(BaseApi):
    @allure.step("查询商品: id={product_id}")
    def get_product(self, product_id: int):
        return self.client.get(f"/api/products/{product_id}")
```

这里不写 base URL，环境地址由配置统一处理。

### 7.2 新建业务用例

创建 `testcases/api/test_product_api.py`：

```python
import allure
import pytest

from api.product_api import ProductApi
from core.assertions import Assert


@allure.feature("商品接口")
@pytest.mark.api
class TestProductApi:
    @pytest.mark.smoke
    @pytest.mark.p0
    def test_get_product_success(self):
        with ProductApi().client as client:
            response = ProductApi(client=client).get_product(product_id=1001)

        Assert.status_code(response, 200)
        Assert.json_value(response, "code", 0)
        Assert.jsonpath(response, "$.data.id", 1001)
```

更推荐直接使用框架 fixture，让 Session 自动关闭：

```python
def test_get_product_success(self, api_client):
    response = ProductApi(client=api_client).get_product(product_id=1001)
    Assert.status_code(response, 200)
```

### 7.3 运行 API 用例

```powershell
python scripts/automation.py test --type api --env uat
```

只跑冒烟：

```powershell
python scripts/automation.py test --type api --env uat --marker smoke
```

只跑一个文件：

```powershell
python -m pytest testcases/api/test_product_api.py --env uat
```

## 8. 根据 Swagger 设计 API 用例

每个接口至少检查：

1. 正常参数。
2. 必填参数缺失。
3. 空字符串、0、负数、最大长度等边界。
4. 不存在的 ID。
5. 无 token、过期 token、无权限账号。
6. 状态码和业务 code。
7. 关键响应字段和数据类型。
8. 写操作后的数据库或查询接口结果。

不要只断言 `status_code == 200`。接口可能返回 HTTP 200，但业务 code 已经失败。

## 9. 登录态和接口场景测试

多个接口需要共享 token 时使用同一个 `api_client`：

```python
def test_create_and_query_order(api_client, env_settings):
    user_api = UserApi(client=api_client)
    order_api = OrderApi(client=api_client)

    login_response = user_api.login(env_settings.username, env_settings.password)
    Assert.status_code(login_response, 200)

    create_response = order_api.create_order(product_id=1001, qty=1)
    order_id = extract(create_response.json(), "$.data.order_id")

    query_response = order_api.get_order(order_id)
    Assert.jsonpath(query_response, "$.data.status", "CREATED")
```

密码、token、Authorization、Cookie、手机号等字段会在框架日志和 Allure 请求附件中自动脱敏。

## 10. 测试数据和自动清理

多组测试数据放入 `data/`，不要把几十组参数硬编码在用例函数里。

使用清理登记器：

```python
def test_create_order(api_client, clean_data):
    response = OrderApi(client=api_client).create_order(product_id=1001, qty=1)
    order_id = extract(response.json(), "$.data.order_id")

    clean_data.add_table("orders", "order_id=%s", [order_id])
    Assert.status_code(response, 200)
```

创建成功后立刻登记清理。即使用例断言失败，teardown 仍会执行。清理失败会让测试明确失败，不会只打印 warning 后继续显示绿色。

## 11. 编写第一个 Web 测试

### 11.1 安装浏览器

```powershell
python -m pip install -r requirements-web.txt
python -m playwright install chromium
```

### 11.2 创建 Page Object

创建 `pages/product_page.py`：

```python
import allure

from pages.base_page import BasePage


class ProductPage(BasePage):
    URL = "/products"
    INPUT_KEYWORD = "[data-testid='product-keyword']"
    BTN_SEARCH = "[data-testid='search-button']"
    RESULT_LIST = "[data-testid='product-list']"

    @allure.step("搜索商品: {keyword}")
    def search(self, keyword: str):
        self.open(self.URL)
        self.fill(self.INPUT_KEYWORD, keyword)
        self.click(self.BTN_SEARCH)
```

优先要求开发提供 `data-testid`。其次使用稳定 `id` 或 role。不要复制很长的绝对 XPath。

### 11.3 创建 Web 用例

创建 `testcases/web/test_product_web.py`：

```python
import pytest
from playwright.sync_api import Page

from pages.product_page import ProductPage


@pytest.mark.web
class TestProductWeb:
    @pytest.mark.smoke
    def test_search_product(self, page: Page):
        product_page = ProductPage(page)
        product_page.search("测试商品")
        product_page.expect_visible(ProductPage.RESULT_LIST)
        product_page.expect_text(ProductPage.RESULT_LIST, "测试商品")
```

### 11.4 运行 Web 用例

后台运行：

```powershell
python scripts/automation.py test --type web --env uat --marker smoke
```

显示浏览器并放慢操作：

```powershell
python scripts/automation.py test --type web --env uat --headed --slowmo 500
```

切换 Firefox：

```powershell
python -m playwright install firefox
python scripts/automation.py test --type web --env uat --browser firefox
```

命令行参数优先于 `config/config.yaml`。`trace: true` 会在失败时保留 trace。

## 12. 编写第一个 App 测试

App 自动化还需要：JDK、Android SDK、模拟器或真机、Node.js、Appium Server 和 UiAutomator2 驱动。完整安装步骤见 [appium-setup.md](appium-setup.md)。

安装 Python 依赖：

```powershell
python -m pip install -r requirements-app.txt
```

启动服务并检查设备：

```powershell
appium
adb devices
```

修改 `config/config.yaml` 中的 `appPackage`、`appActivity` 和 `deviceName`，然后在 `screens/` 写 Screen Object，在 `testcases/app/` 写用例。

运行：

```powershell
python scripts/automation.py test --type app --env uat
```

框架只使用显式等待，不要在 App 用例里写 `time.sleep()`。

## 13. Marker 怎么使用

每个业务用例至少有端类型 marker：

```python
@pytest.mark.api
@pytest.mark.web
@pytest.mark.app
```

常用级别：

- `smoke`：核心链路，每次提交运行。
- `regression`：完整回归，通常每日定时运行。
- `p0`：系统不可用级别核心能力。
- `p1`：重要业务功能。
- `p2`：普通功能和低频场景。
- `prod_safe`：经过审核、只读、允许生产环境执行。

不要随便标记 `prod_safe`。它表示用例不创建、不修改、不删除数据，也不会触发支付、通知或下游业务动作。

## 14. 生产环境保护

普通命令运行生产环境会直接终止：

```powershell
python scripts/automation.py test --type api --env prod
```

只有经过负责人审批，确认账号只读、用例标记为 `prod_safe` 后，才可双重授权：

```powershell
$env:ALLOW_PROD_TESTS="1"
python scripts/automation.py test --type api --env prod --allow-prod
Remove-Item Env:ALLOW_PROD_TESTS
```

即使授权成功，框架也只收集 `prod_safe` 用例。HTTP 客户端只允许访问配置中的同源 API，并且只允许 GET/HEAD/OPTIONS；DB 和 Redis 客户端的直接写方法也会被阻止。

## 15. 报告和失败排查

运行测试后，Allure 原始结果默认在 `reports/allure-results/`。

安装 Allure 命令行后查看：

```powershell
allure serve reports/allure-results
```

Web/App 用例失败时会附加截图。Web 配置开启 trace 后，可以运行：

```powershell
playwright show-trace <trace文件.zip>
```

接口失败优先检查：

1. 状态码和业务 code。
2. Allure 中已脱敏的请求 URL、headers、params 和 body。
3. 实际环境是否正确。
4. token 是否过期。
5. 测试数据是否已被其他用例修改。
6. 后端日志中的 request ID。

```powershell
python -m ruff format .
```

## 18. 接入 CI

仓库包含：

- `.github/workflows/automation-test.yml`
- `.gitlab-ci.yml`
- `Jenkinsfile`

三套流水线都遵循：

1. ruff 静态检查。
2. 离线框架自测。
3. API 和 Web 业务测试并行。
4. PR/push 默认跑 smoke。
5. 定时任务跑 regression。
6. 独立生成 Allure 结果后合并报告。
7. 从 CI Secret 注入账号、密码和通知配置。

需要在 CI 平台配置的变量见 [ci.md](ci.md)。不要把 Secret 写进 YAML 或 Jenkinsfile。

## 19. 常见问题

### `ModuleNotFoundError`

确认已激活 `.venv`，然后安装对应 requirements 文件。

### Playwright 提示浏览器不存在

```powershell
python -m playwright install chromium
```

### pytest 显示没有业务用例

这是新模板的正常状态，但命令会返回失败，避免正式 CI 因目录或 marker 写错而出现假绿色。在 `testcases/api`、`testcases/web` 或 `testcases/app` 创建 `test_*.py` 后再运行。

仅在模板初始化阶段需要临时验证命令入口时，可以显式放行：

```powershell
python scripts/automation.py test --type api --env uat --allow-empty
```

正式 CI 不要使用 `--allow-empty`。

### `unknown environment`

`--env` 指定的名称必须存在于 `config/config.yaml`。

### 接口连接超时

检查地址、VPN、代理、DNS、测试环境是否启动，以及配置中的 URL 是否正确。

### 用例单独通过，并发失败

通常是共享账号、固定测试数据、执行顺序或清理不完整。为每个用例生成唯一数据，并使用 `clean_data`。

### CI 能跑，本地不能跑

比较 Python 版本、依赖版本、环境变量、网络和 Playwright 浏览器版本。先运行 `doctor`。
